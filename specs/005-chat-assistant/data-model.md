# Data model: US-05 Chat assistant

## Tables (migration `0003_chat_tables`, hand-written)

**`chat_conversations`**

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | generated by the service |
| `user_id` | text NOT NULL | token `sub`; every query filters on it |
| `customer_id` | uuid NULL | token `customerId` claim |
| `title` | varchar(200) NULL | trimmed; no auto title |
| `created_at`, `updated_at` | timestamptz NOT NULL | UTC; `updated_at` bumped on each post |

Index `(user_id, updated_at DESC, id)` for listing.

**`chat_messages`**

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | assistant id = `messageId` of the stream |
| `conversation_id` | uuid FK → conversations `ON DELETE CASCADE` | |
| `role` | text CHECK in (`user`, `assistant`) | |
| `content` | text NOT NULL | user: trimmed 1–2000 chars; assistant: text actually sent |
| `finish_reason` | text NULL CHECK in (`completed`, `replaced`, `tool_limit`, `client_disconnected`) | assistant only |
| `prompt_version`, `model_id` | text NULL | assistant only; `model_id` null when no model answered |
| `input_tokens`, `output_tokens` | integer NULL ≥ 0 | assistant only |
| `created_at` | timestamptz NOT NULL | history order `(created_at, id)` |

Index `(conversation_id, created_at, id)`.

**`chat_checkpoints`** (LangGraph state, research §5): `thread_id` text, `checkpoint_ns` text,
`checkpoint_id` text, `parent_checkpoint_id` text NULL, `type` text, `checkpoint` bytea,
`metadata` jsonb, `created_at`; PK `(thread_id, checkpoint_ns, checkpoint_id)`. Only the newest
checkpoint per `(thread_id, checkpoint_ns)` is kept.

**`chat_checkpoint_writes`**: `thread_id`, `checkpoint_ns`, `checkpoint_id`, `task_id`, `idx`
integer, `channel` text, `type` text, `value` bytea; PK `(thread_id, checkpoint_ns,
checkpoint_id, task_id, idx)`. `thread_id` = conversation id (text). Deleting a conversation
deletes its checkpoint rows in the same transaction (FR-004).

## Domain (agents/assistant, frozen Pydantic, `StrEnum`s)

- `FinishReason`: `completed | replaced | tool_limit | client_disconnected`.
- `ChatErrorCode`: `LLM_UNAVAILABLE | BUDGET_EXCEEDED | RATE_LIMITED | TOOL_FAILED | INTERNAL`
  (+ fixed customer-safe message each, FR-009).
- Transcript items (state, JSON-dumped): `UserTurn {text}`, `AssistantText {text}`,
  `ToolCallItem {call_id, name, arguments}`, `ToolResultItem {call_id, name, ok, payload}`
  (payload = envelope or `{error, message}`; never the token).
- `ChatState` (TypedDict): `transcript` (append reducer), `rounds`, `pending_tool_calls`,
  `answer_segments`, `outcome` (`FinishReason | ChatErrorCode | None`), `usage`, `model_id`.
- `StreamEvent` union (contract): `MessageStart`, `Token`, `ToolCall`, `ToolResult`,
  `MessageEnd`, `StreamError`; camelCase aliases; id assigned by the API framer.
- `RunOutcome`: finish reason or error code, sent text, usage, model id, tool stats (for storage
  and the `chat_run` log line).

## Rules and transitions

- Post: count + 2 > 100 → `CONVERSATION_FULL`; active stream → `STREAM_ACTIVE`; user message stored
  before the stream opens.
- Run ending → stored assistant message: `completed`/`replaced`/`tool_limit`/`client_disconnected`
  store one; an `error` ending stores none (user message stays).
- Lock: acquired on post, released on every ending; delete cancels the active run first.
- Ports: `ConversationStore` (create, list, get-with-history, delete, add user/assistant message,
  count) in agents; `ConversationRepository` implements it in `infrastructure/db`.
